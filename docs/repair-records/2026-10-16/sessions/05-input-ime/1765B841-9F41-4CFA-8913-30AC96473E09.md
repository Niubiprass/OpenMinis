但 getter 中没有等值保护。对照较新 HEAD，三个审查文件唯一差异正是：HEAD 为 **1169 行**增加了“仅值变化才赋值”的保护；**v64 尚未包含**。这证明版本差异与具体缺口，不能仅凭后续代码注释认定已经实测根因。

**复现检查：** 关闭/停止助手流式回复，分别用中文拼音与英文持续输入、删除，尤其反复跨越输入框最大高度。在 **1169 行**与 `layoutSubviews()` 设断点/计数，观察同值赋值是否伴随重复布局、`contentOffset` 或框高跳变。若无流式输出仍闪，先查此处。

### 2. 流式正文淡入与前缀比较互相干扰，可造成“闪现后变淡”和短暂不显示

**路径与证据：**

- `src/ios/Views/Chat/TextFadeAnimator.swift:142–155`：新增文字先被写成 `.foregroundColor` **alpha 0**。
- `src/ios/Views/Chat/SelectableMarkdownView.swift:10786–10799`：前缀比较只排除字体相关键，**仍比较前景颜色，包括淡入中的 alpha**。
- 同文件 **10582–10595**：比较失败便执行整段：
  ```swift
  textView.attributedText = attributed
  ```
- 同文件 **10602–10605**：随后继续调度新增范围淡入，整段替换分支自身没有取消旧动画。
- `TextFadeAnimator.swift:213–230`：旧动画仍用已保存范围写回逐帧颜色；只检查范围是否越界，没有检查内容代际。

**触发链：** 新 token 到达时，若前缀比较采样到尚未淡入完成的属性 run，正常渲染颜色与 live storage 的半透明颜色不同，追加更新退化为整段替换。旧文字被整段替换恢复正常颜色，下一动画帧又被旧动画写回半透明，形成**“出现 → 变淡 → 再出现”**。带独立样式的尾词更容易命中；不是每个纯文本 token 都必现。

“新增字暂不显示”也有直接证据：淡入时长为 **0.45 秒（TextFadeAnimator.swift:36）**，批次错开窗口为 **0.10 秒（54 行）**。正常情况下会逐渐显示；主线程卡顿会延迟动画推进。**未发现足以证明永久丢字的证据。**

**复现检查：** 用可控流式源，每 30–80 ms 依次送入：

```text

甲 **乙**
甲 **乙** 丙
```

在 **SelectableMarkdownView.swift:10595** 设断点，确认“乙”淡入未完成时是否走全文替换；随后观察 **TextFadeAnimator.swift:226** 是否再次降低其 alpha。录屏同时核查 `textStorage.string`，区分“内容不存在”和“内容存在但透明”。

**建议方向：** 将显示层淡入状态与正文前缀比较隔离；整段替换前取消/失效旧动画，再调度本次新增范围。**此问题已确认存在于 v64 源码，优先级高于尚未证实的后台重放错序。**
