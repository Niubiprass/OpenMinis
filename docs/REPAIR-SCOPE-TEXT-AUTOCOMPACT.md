# 160648 后续最小修复方案（待实施）

## 用户确认与范围

用户最新反馈：除纯文本输出不够流动、会闪跳/成块出现外，当前没有发现其他问题；留白已大部分感觉不到。只允许修正文流式体验与自动压缩免确认，不扩大范围。本文件是方案，不代表已经修改、编译、安装或验收。

## 一、正文流式体验

目标：减少可避免的“停顿后大段蹦出”，保持已有文字稳定，不让修复退回缺字/空白。

- 先用同一block的最小计时对照delta到达、内容提交、文本存储赋值与显示；仅改被证实的客户端阻塞/重复工作，不将上游本无delta的停顿伪装成已修复。
- 根据证据收窄正文批次合并、尾部增量追加和受影响末段属性更新，避免不必要的整篇赋值及重复重配。
- 不逐token全量解析或布局，不直接重开此前存在风险的alpha透明渐显，不通过人为拖慢输出假造丝滑。
- 保留现有高度/身份/收缩修复。iOS15支持fast-append，iOS16+限制的是fade；不得沿用旧误读。

## 二、自动压缩免确认

用户当前全局自动压缩已开启，不能把要求用户再开一次当修复。

- 历史加载完成后的进入/恢复、发送前与代理循环内，使用一致的开关/预算与压缩判定入口；避免进入后只提示但未执行。
- 已开启自动模式且达到阈值时：直接压缩，不显示“压缩并发送/压缩并开启自动压缩”的确认弹窗。
- 保留当前待发内容/附件；摘要和marker成功提交后，再继续待发消息及已有队列。不增加重复压缩、重复发送。
- 压缩失败时保留内容并明确报错，不假装成功、不无限重试；继续沿用已有失败队列保护，不借机重写恢复系统。
- 沿用现有预算及实际模型窗口限制，不放大上下文上限。保留用户主动关闭自动压缩时的手动模式。
- 截图当次日志只能证明手动分支，不能倒推开关早已开启；按用户期望补足自动触发链，不把未知时序说成已确诊根因。

## 三、明确不改

卡片/工具框/代理卡布局、深度思考展开收起、留白与宿主高度链、已正常的“Minis正在思考…”等待提示、输入框、模型/提供商设置，以及其他无关功能。

## 四、验收标准

1. iOS15.5真机短/长中文纯文本：首字和后续增量及时，已显示正文不闪退/消失；区分传输停顿与客户端延迟。
2. 自动开关开启且到阈值：进入/恢复/发送场景无确认弹窗，直接压缩；落库成功后待发内容只发送一次。
3. 自动模式未到阈值不压缩；明确关闭时尊重手动选择；失败不丢消息。
4. 原主长会话抽测快滑和思考折叠，确认现有留白改善没有回退；该回归测试不授权改动其他逻辑。

最终候选只包含这两项必要修改与对应测试。编译成功不等于真机通过，未安装不称生效。
