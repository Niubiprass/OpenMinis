# MiniSight 0.8.43：直接喊名字（本地接入稿，未发布）

用户已接受原先的本地名字唤醒路线，随后否决“嘿 Siri＋名字”，明确要直接喊宠物名字。此稿延续之前 App 前台、默认关闭的本地边界，不修改系统 Siri、不操作设备或启动麦克风。App HEAD 仍 `82f9fb1`，插件 HEAD 仍 `1e816aa`；此前动作/歌词候选及原有 STATUS 修改保留。

## 界面与结果

首页新增独立“名字唤醒”页：填写 2–8 个汉字名字→本机校读并确认→保存→主动开启“直接喊名字唤醒”。常见字本地转换拼音，多音/生僻字可逐字校读；逐音节和模型词表验证。不把名字插进执行语法，不保证任意名字的识别率。

检测到名字后先停止被动关键词采音，角色回应“我在”，随后接既有短语音入口。转写进入原草稿，仍需手动发送；不会自动发送聊天、执行命令、扩大权限或代替用户批准操作。唤醒后的语音识别/聊天依旧按原配置和独立权限运行，不能统称全部离线。

第一版需要显示端选“App 内”；仅在 Minis 前台、未锁定且宠物已启用时监听。调用时显示模式可由有效命中临时露出角色，对话结束恢复原模式。退出 App、锁屏、隐藏、通话、录屏或其他语音占用时停止；没有 SpringBoard 常驻录音，也不宣称锁屏/被杀后可唤醒。开关默认关闭，用户主动开启才申请麦克风，开启采音会出现系统指示并有额外耗电。

## 接入与保护

- `MiniSightWakeName`：Foundation 本地发音转换、NFC/数字声调/ü校读、2–8汉字和逐token校验；可配置名字与原“用户称呼”分开。
- `MiniSightWakeAssets`：4个模型/词表文件大小及固定 SHA 校验；只读包内模型，无下载/账号读取/音频落盘入口。资源校验在工作队列，不在麦克风回调或界面重绘里做。
- `MiniSightWakeEngine`：直接调用官方 C API，字符串在构造期间持有；后台串行、有界3份音频缓冲和最新准备任务。丢音频段重建流而非拼接旧声学窗口，取消/过期回调失效。没有用常驻 SFSpeech 冒充热词检测。
- `MiniSightWakeController`：权限、前台/锁定/显示端、真实角色宿主、回应和短语音代次统一判断。窗口真实显示后才打开回应面板；关闭、重新打开、键盘接管会立即撤销旧回应，不能迟到再开录音。回应结束留短尾音间隙再复查同一面板，仍不算已验证回声消除。
- `AudioSessionCoordinator` 新增最低优先级 `wakeWord`，任何原音频意图优先，先停止被动采样再换会话。原4意图编号/配置及后台保活顺序保留；`SpeechRecognitionManager` 原直接设置音频会话改经协调器，拒抢VAD录音，只释放自己的占用，初始化失败和取消回收。
- 面板只给新增名字语音增加编辑/发送取消保护；原手动语音入口保留。名字与发音成对保存，日志不写这两个自由文本。设置源码链路由48扩至51，新开关默认关闭。

## 模型与依赖证据

采用 sherpa-onnx v2.0.1 与 ORT 1.28.2 的已下载官方静态 iOS库，用自有最小本地包清单直接引用固定 URL/SHA，不复制无 LICENSE 的包装仓库 Swift 代码。

WenetSpeech mobile 3.3M 模型为 INT8 encoder/joiner＋FP32 decoder，4份运行数据合计 **4,733,039字节**；不带示例关键词或测试录音。模型归档README明确Apache-2.0，许可及来源保存于资源目录。

两库静态扫描 ios-arm64 设备对象：Sherpa280个、ORT1个，platform=iOS、最低系统13.0；这是静态兼容门槛，不等于15.5链接/加载成功。它们用较新SDK构建，新系统符号、与原VAD库共存仍待原生检查。

**正式发布尚有阻断**：Eigen传递头文件许可/对应源码义务、部分 bundled header 版权范围还未闭环。已保存完整已查通知，不宣称全部许可审阅完成；CI在产物打包/上传前保留失败闸门。此时不请求推送或安装。
